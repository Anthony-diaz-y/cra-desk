# Etapa 7 — Web (Next.js) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una web elegante, animada y segura en `web/` que muestra todo CRA Desk: portada pública, login/demo/invitación y la aplicación (plazos, productos y SBOM, hallazgos, editor de reportes, auditoría, claves de API).

**Architecture:** Next.js App Router en el mismo dominio que la API (rewrites de `/api/*`); páginas de la app como componentes de cliente que usan un cliente `fetch` propio (cookie de sesión + CSRF) con TanStack Query. CSP con nonce por petición en `proxy.ts`. Un único cambio en la API: `GET /api/reporting/ai`.

**Tech Stack:** Next.js 16.x, React 19.x, TypeScript, Tailwind 4.x, shadcn/ui (Radix) + lucide-react, motion 14.x, next-themes, @tanstack/react-query 5.x, Vitest 5.x + Testing Library, Playwright 1.65.x. Java 21 / Spring Boot para el endpoint nuevo.

**Spec:** `docs/superpowers/specs/2026-11-15-web-design.md` (padre: `docs/superpowers/specs/2026-11-13-cra-desk-design.md`).

## Global Constraints

- Interfaz en **inglés**; código, commits y API en inglés.
- Solo un comentario de una línea **en español** encima de cada función/componente; ningún otro comentario (TS, Java, CSS, config, scripts).
- Commits sin `Co-Authored-By`; no hacer push (lo hace el usuario).
- Maven wrapper fijado en 3.9.16; tests de la API con `./mvnw clean verify`.
- Nunca guardar sesión, tokens ni claves en `localStorage`/`sessionStorage`; la clave de API recién creada vive solo en el estado del componente.
- Nunca `dangerouslySetInnerHTML`; el Markdown exportado se descarga, no se renderiza.
- Todas las animaciones respetan `prefers-reduced-motion` (`MotionConfig reducedMotion="user"`).
- Contraste AA, foco visible, todo usable con teclado; layout usable a 375 px de ancho.
- Aviso "Support tool, not legal advice" en la portada y en el pie de la app.
- La API se alcanza en `CRADESK_API_URL` (por defecto `http://localhost:8080`); la web en `http://localhost:3000`.

## Review Focus

1. **Sesión vencida a mitad de uso** (la cookie de 8 h expira con la app abierta): la siguiente petición da 401 → la app lleva a `/login?next=<ruta>` sin pantallas rotas. Test en Task 3 (`apiFetch` 401) y Task 5 (redirección).
2. **CSRF perdido tras logout o al entrar por primera vez** (no hay cookie `XSRF-TOKEN`): la primera escritura pide `GET /api/auth/csrf` y reintenta una vez; un 403 por CSRF no se muestra como "demo". Test en Task 3.
3. **Errores de validación de la API** (`errors` por campo en RFC 9457, p. ej. borrador con campo vacío, SBOM SPDX, `sentAt` futuro): se muestran junto al campo, no como alerta genérica. Tests en Tasks 3, 6 y 7.
4. **Reloj cruzando el vencimiento con la página abierta**: la cuenta regresiva llega a 0 y pasa a "Overdue" sin recargar y sin números negativos raros. Test en Task 3 (`formatRemaining`) y Task 7.
5. **Demo intentando escribir**: ningún botón de escritura está habilitado para el rol DEMO, y si una petición devuelve 403 se muestra "Read-only demo". Tests en Tasks 5–8.
